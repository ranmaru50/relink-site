01 / CONCEPT

リンクするのは、
ページではなく能力です。

今日のWebは「モノについてのページ」へリンクできます。しかし、そのモノが今何をできるか、どう呼び出すか、何が必要かまでは共通の方法で表現できません。

RELinkは、エンティティの意味と実行インターフェースを分離しながら結びます。アプリやエージェントは専用連携を知らなくても、能力を発見して適切な方法で実行できます。

01

Entity ≠ Location

存在そのものの識別子と、現在の文書URLを分離します。

02

Capability ≠ Interface

「何ができるか」と「どう実行するか」を別の層として扱います。

03

Semantics before Platform

ブラウザ、ロボット、モバイルを越えて意味を共有します。

04 / AR-XML EXAMPLE

CONCRETE CONTRACT

「何ができるか」と
「どう呼ぶか」を分ける。

この例では、温度を読むという意味的なCapabilityを、HTTP GET Interfaceへ結び付けています。Interfaceが変わっても、Capabilityの意味は変わりません。

<ar-entity
  xmlns="https://relink.dev/ns/arxml/core/0.1"
  version="0.1">
  <capabilities>
    <capability
      id="temperature"
      type="https://example.org/capabilities/temperature/read/1">

      <result>
        <outputs>
          <output name="temperature"
                  type="number" />
        </outputs>
      </result>

      <interfaces>
        <interface type="http"
                   method="GET"
                   endpoint="/api/temperature" />
      </interfaces>
    </capability>
  </capabilities>
</ar-entity>
LOCAL ID
temperature文書内でCapabilityを参照する短い識別子
SEMANTIC CAPABILITY ID
https://example.org/capabilities/temperature/read/1Capabilityの意味を示すグローバルなtype
RETURNS
numbertemperatureというOutput
HOW
HTTP GET/api/temperatureを呼び出すInterface
PRINCIPLE
Capability ≠ Interface
