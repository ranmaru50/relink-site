Real Entity Link

現実世界を、
理解できるWebへ。

RELinkは、モノや設備、ロボットなどの現実のエンティティを、発見・理解・実行可能な能力としてWebへ接続するためのオープンなアーキテクチャです。

Entity identity and document location are deliberately separate.

01 / CONCEPT

リンクするのは、
ページではなく能力です。

今日のWebは「モノについてのページ」へリンクできます。しかし、そのモノが今何をできるか、どう呼び出すか、何が必要かまでは共通の方法で表現できません。

RELinkは、エンティティの意味と実行インターフェースを分離しながら結びます。アプリやエージェントは専用連携を知らなくても、能力を発見して適切な方法で実行できます。

01

Entity ≠ Location

存在そのものの識別子と、現在の文書URLを分離します。

02

Capability ≠ Interface

「何ができるか」と「どう実行するか」を別の層として扱います。

03

Semantics before Platform

ブラウザ、ロボット、モバイルを越えて意味を共有します。

02 / ARCHITECTURE

HOW IT WORKS

小さな部品を、
明確な責務でつなぐ。

RELinkは単一の巨大なサービスではありません。文書、実行環境、名前解決、試験基盤を独立させることで、特定ベンダーやプラットフォームに依存しない実装を目指します。

03 / ONE JOURNEY

ひとつのAnchorから、
ひとつのActionまで。

RELinkの最小の体験は、現実世界の対象に触れ、能力を理解し、実行するまでの連続した流れです。

  1. 01Touch

    QR・NFC・URL・IDから、エンティティへの手がかりを得る。

  2. 02Resolve

    Resolverが永続的なidentityと最新の文書位置を返す。

  3. 03Discover

    RuntimeがAR-XMLを読み、利用可能なCapabilityを公開する。

  4. 04Invoke

    要件を評価し、選択したInterfaceから実際の処理を呼び出す。

04 / USE CASES

FROM LINK TO ACTION

現場ごとに違うモノを、
同じ流れで扱う。

RELinkが共通化するのは製品固有の操作ではなく、対象を見つけ、能力を理解し、条件を確かめて実行するまでの流れです。

UC / 01PUBLIC EQUIPMENT
◎
TOUCH TO USE

その場の設備を
すぐに操作する

利用者が共有設備のQRやNFCに触れると、その機器専用アプリを探さなくても、現在利用できる操作と必要条件を確認できます。

QR / NFC→Resolve→Available actions→Operate
  • 会議室設備
  • 充電器
  • シェア機器
UC / 02FIELD SERVICE
△
IDENTIFY & INSPECT

保守対象を特定し、
診断を実行する

保守担当者は現物のAnchorから正しいEntityへ到達し、モデルや設置場所を推測せずに、その個体が公開する診断Capabilityを呼び出せます。

Asset ID→Entity→Diagnostics
  • 設備保全
  • 点検
  • 遠隔支援
UC / 03ROBOTICS
◇
MULTI-VENDOR CONTROL

異なるロボットの
能力を発見する

制御側はベンダーごとのAPI名ではなく、移動・把持・計測などの意味的なCapabilityを発見し、対応するHTTPやROS Bindingを選択できます。

Discover→Choose binding→Invoke
  • 搬送
  • 協働ロボット
  • 研究開発
UC / 04AI AGENTS
✣
SEMANTIC ACTION

Agentが能力と条件を
理解して実行する

AI Agentは機器固有の事前統合なしに、入力・出力・要件を機械的に読み取り、Runtimeの安全な評価を経てCapabilityを選択できます。

Inspect→Evaluate→Act
  • オートメーション
  • MCP Binding
  • 自律エージェント
