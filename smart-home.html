01 / SYSTEM ARCHITECTURE

FROM ANCHOR TO DEVICE

解決と記述と実行を、
別の責務としてつなぐ。

Resolverは機器を操作しません。AR-XMLはUIではありません。Runtimeは勝手に実行しません。既存のHTTPS APIが最後に機器を制御します。

IMPORTANTResolverの出力はAR-XML Description Locationです。Capability APIやdevice IPを選択せず、AR-XMLを解析・実行することもありません。

01Entity ≠ Location

部屋や照明のCanonical Identityと、現在のAR-XML URLを分けます。

02Capability ≠ Interface

「照明を切り替える」という意味と、POST endpointを分けます。

03Description ≠ Execution

AR-XMLを取得しても機器操作は発生しません。

04Resolution ≠ Authentication

303で到達できても操作権限を得たことにはなりません。

04 / ENTITY DESCRIPTION

AR-XML CORE DRAFT 4

意味的なCapabilityと、
HTTP Interfaceを記述する。

AR-XMLはEntity Interface Description Languageです。画面のボタンや自動化条件、機器側の実装コードは記述しません。

LIGHT / SET STATEPOST JSON · NO OUTPUT
<ar-entity
  xmlns="https://relink.dev/ns/arxml/core/0.1"
  version="0.1">
  <category>home.room</category>
  <capabilities>
    <capability
      id="set-light"
      type="https://example.org/capabilities/light/set-state/1">
      <inputs>
        <input name="on" type="boolean" required="true" />
      </inputs>
      <result>
        <representations>
          <representation media-type="application/json" />
        </representations>
      </result>
      <interfaces>
        <interface
          type="http"
          method="POST"
          endpoint="../api/light/state"
          encoding="json" />
      </interfaces>
    </capability>
  </capabilities>
</ar-entity>
TEMPERATURE / GET CURRENTGET · MULTI-OUTPUT JSON
<capability
  id="get-temperature"
  type="https://example.org/capabilities/temperature/get-current/1">
  <result>
    <outputs>
      <output name="temperature" type="number" unit="Cel" />
      <output name="timestamp" type="string" format="date-time" />
    </outputs>
    <representations>
      <representation media-type="application/json" />
    </representations>
  </result>
  <interfaces>
    <interface
      type="http"
      method="GET"
      endpoint="../api/temperature" />
  </interfaces>
</capability>
CAPABILITY / WHAT照明をON / OFFできるhttps://example.org/capabilities/light/set-state/1
≠
INTERFACE / HOWHTTP POSTで呼び出すhttps://home.example/api/light/state

Capability semanticsはInterfaceから独立しています。将来別のBindingを追加しても、「照明状態を変更する」という意味的Contractは維持できます。

06 / WEB RUNTIME

IMPLEMENTATION UNDER CONTROL

Runtimeは公開する。
Applicationが実行を決める。

現在の公開APIに合わせたL0例です。`load`はAR-XMLを読み込みますが、Capabilityを自動実行しません。

load AR-XML→parse→validate→evaluate→expose Capability
CURRENT PUBLIC API / L0EXPLICIT INVOCATION
const runtime = new ARRuntime();

// 現行baselineでは最終Description URLを直接渡す。
const document = await runtime.load(
  "https://home.example/arxml/living-room.xml"
);

const light = document.getCapability("set-light");
if (!light) throw new Error("Capability not found");

// Human / Applicationの意思決定後にだけ実行する。
await light.invoke({ on: true });
Human↓Web Application↓Web Runtime↓Capability↓HTTP Interface↓Device / Gateway

09 / SECURITY & RESPONSIBILITY

DISCOVERY IS NOT AUTHORITY

見つけられることと、
操作できることを分ける。

PublicなAnchor UUIDやResolution成功は、制御権限の証明ではありません。最終的な操作認可はCapability API側で必ず行います。

Anchor URL≠authorization credential
Resolver resolution≠authentication
AR-XML load success≠permission to control
Capability discovery≠execution authorization
RUNTIME

Capabilityを公開

AR-XMLを検証し、AvailabilityとInterfaceをApplicationへ提示。HTTPS、CORS、mixed-content、Runtime network policyに従います。

APPLICATION

UIとPolicyを判断

Light ON、Brightness 50%、Target 22°Cなどを誰にいつ提示し、どの操作をinvokeするか決定します。

BACKEND

最終認証・認可

Authentication、Authorization、Application policyを強制し、許可された要求だけをDeviceへ渡します。

10 / APPLICATION AUTOMATION

ONE EXPLICIT RULE

自動化するのはRuntimeではなく、
Automation Application。

Applicationが温度を取得し、自身の条件式で判断したあと、別のCapabilityを明示的にinvokeします。

Application→temperature.getCurrent→28°C→if temperature > 27→temperature.setTarget(24)
const reading = document.getCapability("get-temperature");
const target = document.getCapability("set-target-temperature");
if (!reading || !target) throw new Error("Capability not found");

const result = await reading.invoke({});

// 判断主体はApplication。Runtimeは条件を発明しない。
if (Number(result.values.temperature) > 27) {
  await target.invoke({ target: 24 });
}
